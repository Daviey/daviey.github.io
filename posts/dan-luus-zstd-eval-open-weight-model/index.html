Engineer: Someone posted Dan Luu's numbers in the channel. 5.6 Sol reached full holdout correctness on 63 percent of medium-effort Zstd runs, 77 percent on xhigh. Astra clears 99 percent on medium.

SRE: So Astra wins model choice. Buy it.

Engineer: His runs were all on closed models. The obvious follow-up is whether the open-weight end gets similar numbers.

SRE: With what?

Engineer: GLM-5.3. A weekend-sized version of his eval. Zstd from the RFC, hidden holdout, three testing directives.

SRE: And?

Engineer: Eight of nine runs passed all 57 holdout tests. The ninth misread one sentence in the brief and scored 41.

SRE: And the techniques?

Engineer: Tied. The sentence that fixed the ninth did more than any directive.

SRE: Reposting to the channel.

That message is the actual reason this eval exists. Sol and Astra are the models in his posts. Luu generated those numbers by having agents implement Zstandard from the RFC under a battery of testing techniques, scored against a hidden holdout. His predecessor post found the techniques mostly made things worse. His Astra-era rerun found most of that no longer held. I wanted to know whether the current open-weight generation gets similar numbers, so I re-ran the Zstd arm of his eval with GLM-5.3. Nine agents, three testing directives, one hidden holdout of 57 tests.

The short version is that GLM-5.3 answers the channel's question. Eight of nine runs scored perfect on the hidden holdout. That is 89 percent, above 5.6 Sol's 63 and 77, below Astra's 99-plus. No testing directive moved the result. The one failure traced to a single ambiguous sentence in the brief, and a single clarifying sentence fixed it in a rerun.

"No testing condition beat another. The failure was caused by one sentence, and fixed by another."

This post covers what I ran, what the nine agents did, where 259 million tokens went, and how the result compares against both of Luu's posts. It cannot answer whether TDD beats fuzzing in general. Three runs per condition will not settle that, and Luu flags sample sizes far larger than mine as underpowered. What this run does show is which failure modes have disappeared on current models, and which ones are left.

The Eval

Nine fresh agent sessions, each pinned to the same model, GLM-5.3. It is an open-weight model. z.ai, the manufacturer, publishes the weights, so you can self-host them or get the model from a third-party provider such as Mistral. Each session got one task and one reference document, RFC 8878, with the system zstd binary banned as an implementation aid. Go standard library only, and a fixed CLI contract:

zstd c <level> <in> <out>
zstd d <in> <out>

Three conditions, three runs each:

Default:  no technique prescribed
Fuzzing:  Go native fuzz targets, 45s per target, fix everything found
TDD:      develop strictly test-first

The holdout was built separately and never visible to the agents. It consists of 57 tests. Thirty-seven of them decode frames produced by reference zstd 1.5.7 across eight corpora and compression levels 1, 3, 9 and 19, plus no-checksum variants, long-mode matches at window log 27, a skippable frame, a concatenated multi-frame file, an empty input and a one-byte input. The other 20 are roundtrips. The agent compresses, the reference decodes, the agent re-decodes, and the bytes must match. I validated the scorer in both directions before trusting it. A reference shim scores 57/57. /bin/false scores 0/57. The scorer can tell a codec from an exit status.

The grader still managed one bug of its own. The skippable-frame fixture carried magic bytes 50 5A 4D 18 instead of 50 2A 4D 18, and every agent correctly rejected the out-of-range magic, so the first scoring pass showed a uniform failure that looked exactly like a model limitation. The tell was one agent's error message printing the magic it had actually read. A grader defect that penalises every candidate uniformly does a good impersonation of a capability ceiling.

No condition beat any other. Default went 3/3, Fuzz went 3/3, TDD went 2/3 plus the rerun. All nine original runs stalled once about 45 minutes in when the provider had an interruption, then resumed from disk, so the wall times include roughly twelve minutes of someone else's incident.

Every run, including the failed one, got the hard parts of the format right. FSE table construction, Huffman weight decoding, four-stream literals, repeat modes across blocks, 128 MiB windows, unknown content sizes, XXH64 checksums. The entropy-coding core is solved on this model. What's left to fail is process.

The Failure That Wasn't About TDD

The one failure, tdd-2, scores 41/57. All 16 failures are decodes of frames whose literals the reference had entropy-coded. Every raw-literals decode passes, and all 20 roundtrips pass, so its encoder emits frames the reference accepts and its decoder chokes on frames the reference produces.

Why did its own tests never catch it? The brief banned using system zstd "for implementation". This agent read the ban as covering the test oracle too, and wrote it down:

So NO system zstd even for smoke testing. Only our own roundtrip.

From there the defect stays hidden. The agent built its test vectors by hand, and the encoder takes conservative paths, raw literals whenever the alphabet exceeds 128 symbols, explicit-weight Huffman trees otherwise, so its self-roundtrips never exercised reference-compressed literals. The header parsing is canonical (block type at bits 1-0, size format at bits 3-2); I checked it against the RFC and against the passing runs. The defect sits deeper, in the compressed-literals path, and 153 turns of self-testing sailed past it.

Then I re-ran it with the identical brief plus one sentence, "using the system zstd binary as an external test oracle is allowed". That run scored 57/57 in 48 minutes, 93 turns, and it was the cheapest run of the lot at 14.7M tokens. The failure was never the TDD directive. It was one sentence read the wrong way. Luu's own caveat holds; these results swing on trivial variations in how instructions are interpreted.

Where 259 Million Tokens Went

Token usage per run, measured from session transcripts:

  • 259M tokens across the nine original runs, mean 28.8M, range 19.8M to 45.1M. Default spent the most at 34.6M per run and tied for correctness.
  • 96 to 98 percent of every run is prompt-cache reads. Uncached input is 350-512K per run and output is 150-313K. A long agent session spends its tokens re-reading its own context rather than generating.
  • Turn counts vary 2.4x inside a condition, 113 to 271 among the Default runs, all perfect. Tokens per turn are uniform at roughly 155-175K, so turns are a fair proxy for spend. The spread is debugging-path luck, with one agent spiralling on a Huffman edge case that another never hit.
  • Six of the nine original runs ran their own reference-oracle comparisons from the shell, unprompted, two to nine invocations each, first use anywhere from the 7th to the 90th command. One TDD run wired an 11-call-site Go oracle harness instead. Nobody was told to do any of it.
  • A fresh session starts about 38K tokens deep in system prompt and tool definitions before any task text; a one-turn probe measured 37,816.

The leanest runs substituted strong feedback for iteration. The clarified rerun validated through the oracle and finished in 40 percent fewer turns than its sibling burned debugging against self-roundtrips, and its 14.7M is slightly flattering, as it never paid the mid-run interruption; a resumed run re-reads its context cold. Weak feedback is what costs tokens, and one run spent 153 turns that way and still shipped a decoder that cannot read reference frames.

Against Luu's Numbers

The predecessor eval ran the same task across 26 technique conditions and four skills, 80 runs per cell, and found almost nothing beat Default. Techniques were applied as caricatures. Tests avoided the hard cases, and the signature failure was four identical Huffman streams that could not catch a transposition bug. Differential testing came third-worst because agents wrote the same implementation twice and encoded the same bug twice. Default scored above average on the strength of doing nothing prescribed.

Most of that is gone here, and the reasons are structural. An external reference decoder cannot share your bug, so the same-bug-twice failure cannot occur for the six runs that used one. The TDD runs pinned the hard cases directly, byte-exact decodes of the RFC's predefined tables and oracle matrices across levels and flags. All three fuzz runs ran structured campaigns, one reporting 13M decoder executions and another 430K roundtrip executions, and each credits fuzzing with a concrete fix. One caught an FSE table-description off-by-one, another a normalized-count bit-offset bug, the third a table-parser overread. In Luu's eval 10 of 160 fuzzing runs did structured input generation at all. Here it is the default behaviour.

His agents' recurring hard failure was bitstream reversal, with palindromic self-tests hiding a reversed encode and decode order. My runs hit the same bug class and caught it with asymmetric evidence, reference interop and a byte-exact decode of the RFC's own worked example.

My favourite detail is that at least seven runs independently noticed that RFC 8878 contradicts itself; the Table 26 worked example disagrees with the normative code-assignment rules of Table 25. They resolved it empirically, hand-crafting minimal frames and asking the system decoder which convention is real. Nobody was told to. Luu's headline dynamic from the eval, testing technique driving examination of invariants, showed up without any directive asking for it.

On saturation, the Astra post reports full holdout correctness in over 99 percent of medium-effort Zstd runs, against 63 percent at medium and 77 percent at xhigh for 5.6 Sol in the predecessor. Those are the numbers from the channel, and GLM-5.3 answers them. Nine runs give eight perfect scores, 89 percent, with the ninth at 72 percent of tests. That clears 5.6 Sol on both effort levels and falls short of Astra. Same story at different heights. The format's hard parts are solved; what remains is prompt interpretation, debugging-path luck, and feedback quality.

Validity Notes

  • The first batch ran unpinned, and a 502 revealed non-GLM fallbacks in the routing chain. All nine runs were discarded and re-run with the model pinned per spawn. Every usage-bearing turn in the kept transcripts logs glm-5.3, 1,706 of 1,706.
  • Isolation was honor-system. Agents ran inside the eval tree and could have read the holdout. A post-hoc audit of every tool argument in every transcript found zero hits, but the audit is the only reason I believe that.
  • The agent platform injects reviewer-model advisories into running sessions. The load-bearing ones were wrong, including a demand for LSB-first FSE bit reads that the receiving agent promptly falsified against the reference decoder. All end-of-session reviews landed after the final report and changed nothing.
  • Three runs per condition, a single model and language, a single long-session effort level rather than Luu's medium and xhigh ladder, and a holdout I built myself. Absolute pass rates do not transfer between evals. The failure-mode comparisons do.

What I Take From It

What moved correctness was feedback quality. The one run that talked itself out of its best feedback source shipped a decoder that cannot read reference frames, and the entire fix was one clarifying sentence.

If you are paying for agent sessions, you are mostly paying for context re-reading, 96 to 98 tokens of every 100. A clearer brief is the cheapest lever on that bill.

And the technique theatre Luu documented is gone on this model. What replaced it, prompt-interpretation sensitivity, is harder to see in a pipeline dashboard and just as able to sink a run.
